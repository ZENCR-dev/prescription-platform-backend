## 📝 使用指南

### 填写原则
1. **具体化**: 避免模糊描述，使用具体的功能点、接口名、表名等
2. **量化**: 尽量使用数字和百分比来描述影响程度
3. **可验证**: 所有变更项都应该有明确的验证方法
4. **追溯性**: 确保变更原因和决策过程清晰可追溯

### 质量检查清单
- [ ] 变更概述信息完整准确
- [ ] 所有依赖TASK的影响都已评估
- [ ] API变更在APIv1.md中有对应记录
- [ ] 数据库变更有具体的迁移策略
- [ ] 医疗合规影响已充分考虑
- [ ] 迁移路径具体可执行
- [ ] 时间线合理可行
- [ ] 成功标准明确可测

### 审核要求
```yaml
技术审核: architect persona负责技术方案合理性
业务审核: 业务负责人确认需求变更的必要性  
合规审核: 医疗合规专家确认合规性影响
安全审核: security专家确认安全性影响(如适用)
```
