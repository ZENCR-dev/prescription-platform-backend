## 📝 使用说明

### 版本创建工作流
1. **评估阶段**: 使用 `examples/versioning/versioning-trigger-matrix.yaml` 评估是否需要版本化
2. **创建阶段**: 复制当前版本，按 `examples/versioning/naming-and-storage-standards.md` 命名
3. **填写阶段**: 
   - 添加Delta段 (使用 `examples/versioning/delta-section-template.md`)
   - 更新Requirements Snapshot (按 `examples/versioning/requirements-snapshot-evolution.md`)
   - 修改任务分解和验收标准
4. **验证阶段**: 运行质量检查，确保格式和内容完整性

### 质量检查要求
- [ ] 文件命名符合标准格式: `TASK{NN}_v{MAJOR}.{MINOR}.md`
- [ ] Delta段完整填写 (v2.0+版本)
- [ ] Requirements Snapshot正确演进
- [ ] 所有变更都有明确的依据和影响分析
- [ ] 医疗合规要求完整考虑
- [ ] 依赖关系准确记录

### 维护提醒
- 定期检查版本元数据一致性
- 及时归档超期版本文件
- 监控版本使用效果和团队反馈
- 根据实际使用情况优化模板
